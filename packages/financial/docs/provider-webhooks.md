# Provider synchronization and webhooks

**Implementation status:** the API server can mount `/v1/webhooks/stripe` when `stripeWebhook` is injected. The route preserves the JSON text for signature verification. The Stripe verifier checks the HMAC, timestamp, and a bounded snapshot event. `applyProviderEvent` deduplicates by `(provider,eventId)` and advances a bound invoice/subscription status only for newer recognized events. It does not create invoices, grant entitlements, write dunning attempts, or reconcile amounts. PowerTranz has no active callback route.

Verify the exact raw request body and provider signature before parsing JSON. Stripe uses `Stripe-Signature`; PowerTranz verification must follow the merchant-provisioned integration contract. Reply quickly after durable acceptance, then process state work transactionally. Store `(provider,eventId)` first; duplicates are successful no-ops.

Subscribe to payment success/failure/action-required, invoices finalized/paid/overdue/uncollectible/voided, subscription created/updated/deleted/trial-ending, payment method attached/detached, refunds, disputes, and provider-specific asynchronous checkout outcomes. Events can be duplicated or arrive out of order. Compare provider timestamps/state versions and retrieve the provider object when transition ordering is unclear.

Inject `{ verifier: stripeAdapter, actor: trustedActor, sync: financialService }` into `createApiServer({ stripeWebhook })`. The route installs a scoped `application/json` string parser with a 64 KiB limit, verifies before syncing, and returns 200 for accepted or duplicate events. Invalid signatures receive a problem response. Register the endpoint in Stripe for a **snapshot** event destination; thin event shapes need a separate retrieval adapter. Keep `EDU_STRIPE_WEBHOOK_SECRET` in the API host's secret store.

Subscribe to at least `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `invoice.finalized`, `invoice.finalization_failed`, `invoice.paid`, `invoice.payment_failed`, `invoice.payment_action_required`, `invoice.overdue`, `invoice.marked_uncollectible`, `invoice.voided`, `customer.subscription.created`, `.updated`, `.deleted`, `.trial_will_end`, `payment_method.attached`, `.updated`, `.detached`, `payment_intent.payment_failed`, `payment_intent.requires_action`, `refund.created`, `refund.updated`, `charge.dispute.created`, and `charge.dispute.closed`. Implement a handler and test for each event before claiming it mutates local state. Events without a local match are retained as provider events and emit only the generic reconciliation event.

Stripe's [webhook guide](https://docs.stripe.com/webhooks) requires verification against the raw body, warns about duplicate and unordered delivery, and recommends quick acknowledgment. Deduplicating only event ID is insufficient for separate Event objects describing the same resource transition; local state updates also use a provider reference and a timestamp guard. Equal-timestamp conflicts and object changes not represented in our bounded event model still require a provider fetch and reconciliation job. A successful 200 means durable event acceptance, not necessarily fulfillment.

For PowerTranz, obtain the actual merchant package specifying: environment/base URL and credential headers; hosted-page request/redirect protocol; server-to-server callback endpoint, signature/MAC and timestamp/replay rules; transaction query and status codes; 3DS challenge/finalization behavior; tokenization and card-on-file consent; auth/capture/void/refund idempotency and partial amounts; test vectors; and failure/retry semantics. Implement those in a provider adapter and add a route only after signed callback tests can prove authenticity. The public [developer portal](https://powertranz.com/developers) does not supply this complete contract.
