# Financial events and audit contract

All outbox events use topic `financial`, version `1`, and an `occurredAt` timestamp. They are appended in the same serializable transaction as the local state they describe. Publish the outbox after commit; consumers must deduplicate by the outbox event ID and tolerate repeat or out-of-order delivery. Audit actions use the same dotted name for local mutations unless described otherwise. Payloads contain identifiers and bounded metadata only; fetch details through an authorized reader. Never put SPI tokens, card data, secrets, raw webhook bodies, or provider messages into an event.

The legacy status-only sync catalog also defines provider signal names: `financial.invoice.paid`, `.finalized`, `.uncollectible`, `.voided`; `financial.subscription.updated`, `.canceled`, `.trial_ending`; `financial.dunning.payment_failed`, `.action_required`, `.payment_succeeded`, `.overdue`, `.exhausted`; `financial.payment_method.attached`, `.detached`; and `financial.payment.refunded`, `.disputed`. Their payload shape is `{ provider, eventId, type }`. The current status-only sync emits a specific signal only for a recognized subscription transition; all other accepted provider events use `financial.provider-event.applied`. These catalog names are reserved for future handlers and must not be treated as confirmed local fulfillment, refund, or entitlement changes.

The store events above are emitted inside the same transaction as their local state and audit records. An authenticated Google full void creates a durable order tombstone before any entitlement sync. A later claim for that order remains revoked, even if Play reports an active token. `financial.store-notification.review_required` needs a consumer that investigates the store's order/void history; it does not adjust access automatically. `financial.store-subscription.billing_failed` is a store-managed retry signal, not a local dunning charge attempt. The audit trail records the trusted actor, resource, correlation ID, source, outcome, and the bounded change fields. The operational log is separate and best effort. `financial.provider.unavailable` reports missing provider configuration; `financial.powertranz.callback.failed` reports a callback failure with a transaction ID only. Neither operational event changes financial state.
