# Set up Stripe

1. Set `EDU_STRIPE_SECRET_KEY` and `EDU_STRIPE_WEBHOOK_SECRET` in the host's secret configuration; see [`packages/api/.env.example`](../../../packages/api/.env.example). `readFinancialConfiguration` creates the adapter only when both are present and reports `financial.provider.unavailable` otherwise.
2. Create an HTTPS **snapshot event** webhook destination at `https://<host>/webhooks/stripe` and use its signing secret. Select Checkout session completed, async succeeded/failed and expired; invoice finalized, paid, payment succeeded/failed/action required, overdue, uncollectible and voided; subscription created/updated/deleted/trial ending; payment method attached/updated/detached; refund updated; charge refunded and dispute created/closed. Check Stripe's current [event catalog](https://docs.stripe.com/api/events/types) before expanding the handler. The adapter verifies raw-body `Stripe-Signature` and a five-minute timestamp window.
3. Issue a local invoice with immutable lines, create a hosted Checkout session for its exact total, and bind the Checkout session ID to that invoice. Inject `stripeWebhook: { verifier: stripeAdapter, actor: trustedSyncAgent, sync: billingService }` into `createApiServer`. A paid session event with matching session ID, payment intent, currency and amount creates the local payment and entitlements. The success URL is for display only. Stripe recommends server-side [post-payment fulfillment](https://docs.stripe.com/payments/existing-customers?platform=web&ui=stripe-hosted).

`billing.applyProviderEvent` deduplicates Stripe event IDs. It also records matched dunning failures, confirmed `refund.updated` credit notes, and detached method state; unmatched types remain in provider-event history for reconciliation. Configure `dunningSchedule` and `revokeOnFullRefund` in the sync wrapper according to product policy. Stripe subscription creation and collection scheduling need host orchestration as described in [subscriptions](./subscriptions-and-trials.md). The [webhook guide](./provider-webhooks.md) identifies which subscribed event types have concrete local effects.
