# Dunning: failed collection and customer action

For a confirmed failed attempt on an open invoice, a trusted agent calls `billing.recordDunningFailure({ actor, audit, userId, invoiceId, providerEventId, failureCategory, providerFailureCode?, requiresCustomerAction, schedule })`. `schedule.delaysSeconds` is a bounded ordered array of retry delays; `graceSeconds` is retained as policy input but the host currently applies grace. The service assigns an attempt number, stores a bounded failure category/code, customer-action flag, next retry time or exhausted state, and unique provider event ID. It audits and emits one of `financial.dunning.failure_recorded`, `.action_required_recorded`, or `.exhausted_recorded`. Replaying the same provider event returns the existing attempt. A customer-action failure is not treated as exhausted merely because no automatic retry delay exists.

`billing.applyProviderEvent` does this automatically for a bound local Stripe invoice receiving `invoice.payment_failed`, `invoice.payment_action_required`, or `checkout.session.async_payment_failed`. Pass a deliberate `dunningSchedule` to the billing sync host; omitted policy has no retries. PowerTranz declined Sale records a `payment_declined` action-required attempt. An unmatched provider event is recorded for reconciliation but cannot create a dunning attempt against an unknown invoice.

The host must run a scheduler that claims due attempts, checks the provider's current invoice/payment state, checks whether the customer has supplied a new method, and then invokes the provider's documented retry API. Do not retry an action-required 3DS/SCA failure blindly. The scheduler must write the next provider event and update notification state; this package currently stores the schedule but does **not** initiate an off-session charge or send notices. `graceSeconds` is not yet an access cutoff engine. Retain current paid-period grants until their dates expire or an explicit, audited access decision revokes them.

Treat finalization failures, overdue/uncollectible invoices, disputes, expired Checkout sessions, and failed PaymentIntents as distinct states. The provider's [Stripe event types](https://docs.stripe.com/api/events/types) are signals; a failed attempt does not itself cancel a subscription or erase a paid invoice.
