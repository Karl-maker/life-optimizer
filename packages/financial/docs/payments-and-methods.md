# One-off payments and payment methods

## Stripe Checkout

Issue an invoice first, then call `StripeAdapter.createOneOffCheckout` with the exact invoice minor amount/currency, an account lookup key, an idempotency key, short description, and HTTPS success/cancel URLs. Bind the returned Checkout session ID to the invoice with `billing.bindInvoiceProvider`. The browser redirect is only a navigation result. Configure `/v1/webhooks/stripe` with the same adapter as verifier and `billing.applyProviderEvent` as sync. A signed `checkout.session.completed` with `payment_status=paid`, or `checkout.session.async_payment_succeeded`, records the payment and fulfills access only when the session ID, amount, currency, and payment intent match. The full flow and its event limits are in [provider webhooks](./provider-webhooks.md).

PowerTranz uses its own hosted Sale and browser return. Follow [PowerTranz](./powertranz.md); do not pass card fields through this API.

## Payment method metadata

After a PCI-compliant provider has attached a method to the intended customer, a trusted agent calls `financial.registerPaymentMethod` with `provider`, opaque `tokenReference`, optional brand, last four digits, and expiry month/year. `getPaymentMethod` and `listPaymentMethods` return display metadata without the token. `updatePaymentMethod` changes the display metadata; `revokePaymentMethod` soft-revokes a local row. The database has a unique `(provider,tokenReference)` constraint. A client-supplied token by itself does not prove provider ownership. Never store PAN, CVC/CVV, magnetic stripe data, cardholder authentication data, or raw provider response.

`billing.setDefaultPaymentMethod` selects an active method owned by the account or clears the local default with `null`; `billing.markPaymentMethodDetached` marks confirmed provider detach and clears the local default if necessary. Both audit and emit events. For Stripe, `stripeAdapter.setDefaultPaymentMethod({ customerId, paymentMethodId })` verifies method ownership before updating the customer's invoice default, and `stripeAdapter.detachPaymentMethod` verifies ownership before detaching. Call the provider first, then the corresponding local billing method. If the local commit fails after provider success, reconcile it from provider state; do not retry a provider detach blindly. PowerTranz token detach and card-on-file ownership are not established by the supplied merchant material, so no provider-side PowerTranz method operation is exposed.

For a saved Stripe method, use a provider-created SetupIntent or Checkout consent flow and verify `payment_method.customer` against the account's Stripe customer ID before registering metadata. The local account does not yet store a provider customer mapping or orchestrate that consent flow. Consult Stripe's current [payment method](https://docs.stripe.com/api/payment_methods) and [customer](https://docs.stripe.com/api/customers) APIs before adding provider-side mutation. No automatic off-session charge is made by this package.
