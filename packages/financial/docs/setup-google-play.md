# Set up Google Play purchases

1. Create a one-time product or subscription in Play Console, and create the local product/price that describes its entitlement. Map the exact Play product ID with `store.mapProduct({ provider: "google", sku, priceId, actor, audit })`. This adapter accepts one Play line item per token; multi-item purchases need additional mapping work. Google owns actual price, tax and receipt data.
2. Enable the Google Play Developer API and grant a service account the required Play Console API access. Use Application Default Credentials (for example, `GOOGLE_APPLICATION_CREDENTIALS` pointing to a secret-mounted JSON file, or workload identity). Set `EDU_GOOGLE_PLAY_PACKAGE_NAME`. The server uses `purchases.productsv2.getproductpurchasev2` for one-time products and `purchases.subscriptionsv2.get` for subscriptions. Play's [backend guide](https://developer.android.com/google/play/billing/backend) requires server-side verification before granting entitlements.
3. Create a Cloud Pub/Sub topic; grant `google-play-developer-notifications@system.gserviceaccount.com` **Pub/Sub Publisher**. In Play Console's Monetization setup enable RTDN and choose **all subscription and one-time product notifications** so one-time purchases and voids arrive too. Create an authenticated push subscription to `https://<host>/webhooks/google-play` with a dedicated push service account and audience equal to that exact HTTPS URL. Set `EDU_GOOGLE_PUBSUB_AUDIENCE` and `EDU_GOOGLE_PUBSUB_SERVICE_ACCOUNT_EMAIL`. The adapter verifies Google's signed OIDC token, exact audience, verified email and package name before calling the Play API. See [Play RTDN setup](https://developer.android.com/google/play/billing/getting-ready) and [authenticated Pub/Sub push](https://docs.cloud.google.com/pubsub/docs/authenticate-push-subscriptions).
4. Before BillingClient purchase, derive a stable non-reversible obfuscated account ID in your host, bind `iap.google.<id>` to the user, and set BillingFlowParams `setObfuscatedAccountId(id)`. After BillingClient returns a purchase token, the authenticated app calls `POST /store-purchases/google/claim` with `{ "purchaseToken": "...", "kind": "one_time" }` or `"subscription"`. The server queries Play, checks the verified account ID and SKU mapping, records the purchase and grants access only for a completed purchase. It then acknowledges the purchase through Play. If acknowledgement fails, retry the claim; the local ledger is idempotent. Never log or persist the raw token; only its SHA-256 hash is stored.

The RTDN endpoint uses `messageId` for replay protection, decodes the Pub/Sub message, and calls the Play Developer API for **current** product/subscription state. It tracks one-time `PURCHASED`, `PENDING`, `CANCELLED`; subscription active, grace, canceled, paused, on hold and expired; plus full voids. A canceled subscription keeps access through its verified expiry, while hold/pause suspends and recovery can restore it. An authenticated full void names the exact order ID and token hash, including an older renewal order, so only that order's grants are revoked. Unknown orders, quantity-based partial voids and pending refund reviews emit a review event without guessing which entitlement amount to adjust. See Google's [RTDN reference](https://developer.android.com/google/play/billing/rtdn-reference) and [one-time lifecycle](https://developer.android.com/google/play/billing/lifecycle/one-time).

Use Play's Voided Purchases API and subscription/product query APIs in a scheduled reconciliation job for missed events. The current package does not run that job, initiate refunds or handle multi-line Play purchases. It emits the event catalog in [events](./events.md). `readStoreProviderConfiguration` reports `financial.provider.unavailable` when the Google settings are missing; no Google route should be mounted until the adapter is ready.
